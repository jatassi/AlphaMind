5Findings — load-bearing

load-bearing P5 P3

Float used for monetary fields across the domain and persistence layers

Where
src/myproject/domain/order.py:42, src/myproject/domain/pricing.py:15-30, src/myproject/persistence/models.py:88
Why it matters
Lorem ipsum dolor sit amet, consectetur adipiscing elit. Float arithmetic accumulates rounding error that surfaces at end-of-day reconciliation, and a primitive float field carries no currency, no scale, and no rounding contract. Violates P3 (illegal states unrepresentable) and P5 (frozen-dataclass internals): money should not be a primitive crossing every layer.
Fix
Introduce a Money value object backed by Decimal with explicit currency. Replace float at the boundary; convert once at ingest. See references/data-and-types.md §D3.
# Current
def calculate_total(price: float, qty: int) -> float:
    return price * qty

# Proposed
def calculate_total(price: Money, qty: Quantity) -> Money:
    return price * qty
load-bearing P9 A5

Pure helpers in utils.py extracted only for testability — bugs displaced into call sites

Where
src/myproject/utils.py:1-600, src/myproject/helpers.py:1-180
Why it matters
Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt. Twelve single-line pure helpers are individually well-tested, but the call sites that orchestrate them (in services/order.py and services/billing.py) are uncovered. The bug surface migrated; the test coverage didn't follow. Violates P9 — the modules are shallow and the seam between them is the real bug surface.
Fix
Collapse the helpers into the calling module, expose one or two well-named entry points, and test at the boundary. Delete the now-redundant per-helper tests (references/testing.md §J1 "replace, don't layer").
